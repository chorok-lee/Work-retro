# 업무 회고

개인 업무 루틴을 매일 체크하고, 주 단위로 돌아보는 트래커입니다.
[habit-track](https://github.com/chorok-lee/habit-track)의 기본 기능(노션 연동 체크, 주간 목표, 회고 화면)을 그대로 가져오고, 감성 연출과 협업 기능을 덜어낸 별도 서비스입니다.

## habit-track과 달라진 점

| 구분 | 내용 |
|---|---|
| 유지 | 노션 DB 연동(체크 = 기록 DB에 행 생성, 해제 = 보관), 항목별 주간 목표(매일 / 주 N회), 날짜 이동, 이번 주 진행률, 지난주 같은 요일 대비 페이스 그래프, 최고 기록 주, 항목별 잔디·연속 기록·주간 달성률·월별 기록, 노션 미연결 시 브라우저 저장, 캐시로 즉시 표시, 앱 복귀 시 자동 새로고침 |
| 제거 — 감성 | 인사 스플래시, 별자리·밤하늘 그래픽, 목표 달성 폭발 효과, 이모지, 🔥·🏆 같은 장식, 감성 문구 |
| 제거 — 협업 | 초록/소운 탭과 전환 버튼, 상대 진행률, 칭찬 카드, 별똥별 편지(`/api/messages`) |
| 변경 | 라이트/다크 자동 전환되는 차분한 업무용 UI, 용어 "습관" → "할 일", 탭 "할 일 / 레슨런 / 회고" |
| 추가 | 레슨런: 그날 배운 점을 한 줄로 남기고, 회고 탭에서 이번 주 레슨런을 함께 봄 |

## 화면

- **오늘**: 평일(월~금) 날짜를 고르면 두 영역이 나옵니다. 토·일은 건너뛰며, 주말에 열면 직전 금요일이 열립니다.
  - **오늘 할 일**: 노션 과업 DB(`26 과업 목록`)에서 **마감일이 그날**인 과업입니다. 체크 = 노션 `완료`, 이름을 누르면 바로 수정, 맨 아래 줄에서 새 할 일 추가(마감일 = 그날, 쓰기 시작하면 나오는 노션 우선순위 선택지 중 하나를 고를 수 있음). 헤더의 **관리하기**를 누르면 노션 과업 목록이 열립니다. 노션에서 추가·수정한 내용은 앱으로 돌아올 때와 화면을 켜 둔 동안 1분마다 다시 불러와 반영됩니다. 우선순위가 `폐기`인 과업은 숨깁니다.
  - **매일 루틴**: 생산성을 위해 매일 지키는 습관입니다. 헤더의 **관리하기**를 누르면 노션의 루틴 DB가 열립니다.
  - **하루 평가하기**: 별 1~5개를 고르고 **제출하기**. **레슨런 쓰기**를 누르면 작성 화면이 열립니다.
    - 레슨런은 카드 한 장 = **상황/문제 + 해볼 것** 한 단위입니다(한쪽만 적어도 됨). 아래 **+ 레슨런 추가**로 다음 카드를 만듭니다.
    - 상황/문제를 다 쓰고 해볼 것이 비어 있으면, 해볼 것 칸 안에 제안이 한 번 나옵니다. **넣기**/**닫기**를 누를 때까지 그대로 있습니다.
    - 작성 화면의 **저장**을 누르면 바로 노션에 카드마다 한 행으로(자동 `태그`와 함께) 저장되고 회고에 나타납니다.
    - 해볼 것으로 이어지지 않은 상황/문제가 있으면 **해볼 것 제안**이 뜹니다. **추가**한 것만 저장되고 **넘기기**는 버립니다. `ANTHROPIC_API_KEY`가 있으면 Claude가 문맥을 보고 제안하고, 없으면 규칙 기반으로 제안합니다.
    - 작성 중인 내용은 날짜별로 기기에 남아 있어, 작성 화면을 닫거나 앱을 껐다 켜도 이어 쓸 수 있습니다. 평소엔 목록 아래에 접혀 있고, 오늘 **저녁 6시부터 자정까지는 맨 위로 올라와 펼쳐집니다.**
- **한 주 = 평일 5일**: 주간 목표·페이스 그래프·잔디·연속 기록 모두 월~금 기준입니다. "매일"은 주 5회, 주 6~7회로 적힌 목표도 5회로 봅니다.
- **회고**: 건강 앱 요약처럼 카드 네 장(루틴, 할 일, 하루 평점, 레슨런)만 보여 줍니다. 카드를 누르면 자세한 화면이 열립니다.
  - **루틴**: 이번 주 누적 체크를 지난주 같은 요일까지와 비교한 그래프, 현재 페이스로 달성 가능한 목표 수, 최고 기록 주, 루틴별 최근 3주 잔디와 연속 기록. 루틴을 누르면 1년 잔디·통계·월별 기록이 있는 상세 화면이 열립니다.
  - **하루 평점**: 최근 4주 평일 막대와 최근 평가 목록.
  - **할 일**: 이번 주(월~금) 마감 과업 기준. 핵심 과업을 모두 끝냈는지, 우선순위별 몇 개 중 몇 개 끝냈는지, 남은 핵심·높음 과업, 최근 4주 기록.
  - **레슨런**: 주차별 목록. 각 레슨런의 ⋯ 메뉴에서 수정·삭제합니다.


## 준비

### 1. 노션 DB

**과업 DB (오늘 할 일)** — 기존 `26 과업 목록` DB를 그대로 씁니다(`NOTION_TASKS_DB`로 다른 DB 지정 가능). 이 DB는 `업무 회고` 페이지 밖에 있으므로 **DB의 `···` → Connections에 Integration을 따로 추가**해야 합니다.

| 속성 | 타입 | 쓰임 |
|---|---|---|
| 이름 | title | 할 일 |
| 마감일 | date | 이 날짜의 '오늘 할 일'에 표시 |
| 완료 | checkbox | 앱의 체크와 동기화 |
| 우선순위 | select | 핵심·높음·보통·낮음 순 정렬, `폐기`는 숨김 |

**루틴 DB** (코드·환경 변수에서는 items)

| 속성 | 타입 | 쓰임 |
|---|---|---|
| 이름 | title | 할 일 이름 |
| 활성 | checkbox | 켜진 것만 표시 |
| 목표 빈도 | select (`매일`, `주5회`, `주3회` …) | 주간 목표 횟수 |
| 시작일 | date (선택) | 없으면 페이지 생성일 |

**기록 DB**

| 속성 | 타입 | 쓰임 |
|---|---|---|
| 날짜 | date | 기록 날짜 |
| 항목 | relation → 할 일 DB | 어떤 할 일인지 |

**레슨런 DB**

| 속성 | 타입 | 쓰임 |
|---|---|---|
| 내용 | title | 상황/문제 |
| 날짜 | date | 기록 날짜 |
| 해볼 것 | text | 상황/문제에서 이어지는 다음 행동 |
| 태그 | multi_select | 저장할 때 자동으로 뽑은 주제 |

**하루 평점 DB**

| 속성 | 타입 | 쓰임 |
|---|---|---|
| 이름 | title | 날짜 문자열 (자동 입력) |
| 날짜 | date | 평점을 매긴 날 |
| 점수 | number | 1~5 |

레슨런·하루 평점 DB는 제목에 "레슨런" / "평점"이 들어 있으면 자동으로 찾습니다(`NOTION_LESSONS_DB` / `NOTION_RATINGS_DB`로 직접 지정 가능). 연결되지 않으면 해당 기능만 이 기기에 저장되고 나머지는 그대로 동작합니다.

레슨런 DB는 제목에 "레슨런"이 들어 있으면 자동으로 찾습니다(`NOTION_LESSONS_DB`로 직접 지정 가능). 연결되지 않으면 레슨런만 이 기기에 저장되고, 나머지는 그대로 동작합니다.

속성 이름이 조금 달라도 타입이 맞으면 자동으로 찾습니다. 두 DB 모두 `···` → **Connections**에 Integration을 연결해야 합니다.

> 기존 habit-track의 습관 DB / Daily Logs DB를 그대로 연결해도 동작합니다. 이때 `NOTION_OWNER`에 내 이름을 넣으면 내 소유 항목만 보입니다.

### 2. Vercel 배포

1. https://vercel.com → **Add New… → Project** → `chorok-lee/Work-retro` 저장소 Import
2. Framework는 Vite로 자동 인식됩니다 (`vercel.json`에 고정).
3. **Environment Variables**에 아래 값을 넣고 Deploy

| Key | 필수 | 값 |
|---|---|---|
| `NOTION_TOKEN` | ✓ | 노션 Integration 토큰 |
| `NOTION_ITEMS_DB` | ✓ | 할 일 DB ID (노션 DB 주소의 32자리) |
| `NOTION_LOGS_DB` | ✓ | 기록 DB ID |
| `NOTION_LESSONS_DB` | | 레슨런 DB를 제목으로 못 찾을 때만 |
| `NOTION_RATINGS_DB` | | 하루 평점 DB를 제목으로 못 찾을 때만 |
| `ANTHROPIC_API_KEY` | | 레슨런 '해볼 것' 제안을 Claude로 (없으면 규칙 기반) |
| `NOTION_TASKS_DB` | | 오늘 할 일에 쓸 과업 DB (기본: 26 과업 목록) |
| `NOTION_OWNER` | | 기존 습관 DB를 쓸 때, 표시할 소유자 값 |
| `NOTION_OWNER_PROP` | | 소유자 속성 이름을 자동으로 못 찾을 때 |

환경 변수는 배포 시점에 읽히므로, 바꾼 뒤에는 재배포해야 합니다. 연결 후에는 Production Branch로 지정한 브랜치에 push하면 자동 배포됩니다.

### 3. 확인

배포 주소에서 항목을 하나 체크하고 노션 기록 DB에 행이 생기는지 확인합니다. 정상일 때는 화면에 상태 표시가 없고, 문제가 있을 때만 상단에 노란 안내줄이 뜹니다. `https://(주소)/api/schema`에서 두 DB의 속성을 직접 볼 수 있습니다.

## 문제 해결

| 안내 문구 | 조치 |
|---|---|
| 노션 설정이 비어 있습니다 | 빠진 환경 변수를 추가하고 재배포 |
| 토큰이 올바르지 않습니다 (401) | 토큰을 다시 복사해 교체 후 재배포 |
| 데이터베이스를 찾을 수 없습니다 (404) | DB의 Connections에 Integration 연결, DB ID 확인 |
| 노션에서 가져온 할 일이 없어요 | 할 일 DB에 '활성'이 켜진 행이 있는지 확인 |
| 레슨런 DB에 연결하지 못해… | 레슨런 DB가 Integration에 연결됐는지 확인 |
| API 서버에 연결하지 못해… | `npm run dev`는 `/api`를 띄우지 않습니다. 로컬에서는 `vercel dev` |

## 로컬 실행

```
npm install
npm run dev      # 화면만 (브라우저 저장 모드)
vercel dev       # /api 포함 (vercel env pull 로 .env.local 준비)
```

## 파일 구조

```
api/
  _notion.js   노션 호출 공용 코드 (서버 전용)
  items.js     GET /api/items — 할 일 목록
  logs.js      GET/POST/DELETE /api/logs — 기록 조회·체크·해제
  lessons.js   GET/POST/PATCH/DELETE /api/lessons — 레슨런(상황/문제 + 해볼 것) 조회·추가·수정·삭제
  ratings.js   GET/PUT /api/ratings — 하루 평점 조회·저장
  tasks.js     GET/POST/PATCH /api/tasks — 할 일 조회(하루·기간)·추가(우선순위 포함)·수정
  suggest.js   POST /api/suggest — 레슨런 '해볼 것' 제안 (Claude 또는 규칙)
  _keywords.js 레슨런 자동 태그·줄 나누기·규칙 기반 제안 (서버·앱 공용)
  schema.js    GET /api/schema — DB 속성 확인 (진단용)
src/
  App.jsx      화면 전체
  main.jsx     시작점
```
